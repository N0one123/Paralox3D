Installation

Install the Python package with:

python -m pip install paralox3d

For a source checkout, build the native core with:

python -m paralox3d build
0.1.1: This page documents the expanded 0.1.1 API. The native core is still early-development and platform support continues to grow.

Your first game

from paralox3d import *

cube = Object("cube", position=(0, 0, -5))
cube.color = electric_blue

def update():
    cube.rotation.y += 60 * dt

start()

Create objects, put per-frame behaviour in update(), and call start(). The default engine context and loop are handled for you.

Basics

Objects

player = Object("cube", position=(0, 1, 0), scale=(1, 2, 1), name="Player")

The first argument is the model/primitive name. The current native renderer provides a cube primitive. Objects expose their model, name, transforms, collider, tags, components, appearance, and lifecycle state.

Transforms

cube.position = (2, 1, -5)
cube.x = 3
cube.y += 1
cube.rotation = (0, 45, 0)
cube.scale = (2, 1, 2)

cube.move(1, 0, 0)
cube.rotate(0, 15, 0)
cube.scale_by(2)

Transform vectors are Vec3 values. Parent-child hierarchy supports local transforms as well as world transforms.

parent = Object("cube", position=(0, 2, 0))
child = Object("cube", position=(2, 0, 0), parent=parent)

child.local_position
child.local_rotation
child.local_scale
child.parent
parent.children

Useful direction and targeting helpers include forward, right, up, look_at(), distance_to(), move_forward(), move_right(), and move_up().

Game loop and dt

update() is called every frame. You do not pass dt into it. Import the global dt and use it directly.

speed = 5
def update():
    player.x += speed * dt

dt is the elapsed time since the previous frame, allowing frame-rate-independent movement.

Appearance, visibility, and colors

Visual state is reactive: changing a property immediately pushes the state to the native renderer.

cube.rotation = (0, 45, 0)
cube.color = hot_pink
cube.opacity = 0.8
cube.visible = True
cube.enabled = True

color accepts an RGB tuple with values in the 0..1 range. Named colors are exported directly from paralox3d.

cube.color = red
cube.color = gold
cube.color = electric_blue
cube.color = neon_green
cube.color = hot_pink
cube.color = lavender

The 0.1.1 palette includes basic, light/dark, CSS-inspired, and game-friendly names such as red, crimson, orange, gold, yellow, lime, green, emerald, teal, cyan, sky_blue, blue, navy, purple, violet, indigo, magenta, pink, hot_pink, brown, white, gray, black, plus electric_blue, neon_blue, neon_green, neon_pink, neon_purple, neon_yellow, neon_orange, fire, poison, and energy.

opacity is stored as part of object visual state; actual native blending support is still evolving.

Camera

modes.camera = True
camera.position = (0, 2, 8)
camera.look_at((0, 0, 0))

The camera exposes x, y, z, position, pitch, yaw, and roll. look_at() accepts a position or vector-like target.

Native camera controls support mouse interaction: left-drag rotates the camera and right-drag pans it when camera mode is enabled.

Input

if held("w"):
    player.z -= 5 * dt

if pressed("space"):
    print("Jump!")

bind("move_left", "a")
bind("move_right", "d")
if action("move_left"):
    player.x -= 4 * dt
if action_pressed("jump"):
    player.y += 1

Use key(), held(), any_held(), and pressed() for direct keyboard state. Actions map a named action to one or more keys.

Mouse

print(mouse.position)
print(mouse.dx, mouse.dy)

if mouse.left:
    print("Left mouse held")

if mouse.pressed("left"):
    print("Left mouse pressed")

Mouse state includes position, per-frame movement deltas, button held state, and button press events. The engine synchronizes it before your update() callback.

Collision and spatial queries

Objects receive a default Collider. Colliders use axis-aligned bounding boxes and expose size, offset, enabled state, trigger state, layer, and collision masks.

player.collider.size = (1, 2, 1)
player.collider.offset = (0, 0.1, 0)
player.collider.enabled = True
player.collider.is_trigger = True
player.collider.layer = "player"
player.collider.collides_with = {"enemy", "ground"}
if Collision(player, wall):
    print("Hit!")

for other in Collision(player):
    print("Touching:", other.name)

Raycasts and casts

hit = raycast((0, 1, 5), (0, 0, -1), distance=20)
hit = boxcast((0, 1, 5), (1, 1, 1), (0, 0, -1), distance=20)
hit = spherecast((0, 1, 5), 0.5, (0, 0, -1), distance=20)

Cast results are RaycastHit objects with object, point, normal, and distance. Query helpers overlap_box() and overlap_sphere() return matching objects.

Use the optional ignore argument on casts and overlap queries to exclude objects.

Timers

after(2.0, lambda: print("Two seconds!"))

timer = every(1.0, lambda: print("Tick"))
timer.cancel()

one_shot = Timer(3.0, callback=lambda: print("Done"))
one_shot.reset()

Timers are frame-driven. after() schedules a one-shot callback and every() schedules a repeating callback. Timers can be cancelled and reset.

Components

from paralox3d import Component, Script

class Health(Component):
    def __init__(self):
        self.value = 100

player = Object("cube")
health = player.add(Health())
print(player.get(Health).value)

Components attach behaviour or data to objects. The public API includes Component, Script, FPSController, and CharacterController. Components receive lifecycle/update calls through the engine.

Scenes

scene = Scene("Level1")
scene.create("cube", position=(0, 0, -5), name="Start")
scene.create("cube", position=(2, 0, -5), name="Wall")
scene.enter()

scene.save("scenes/Level1.scene")
loaded = Scene.load("scenes/Level1.scene")
Scene.switch(loaded)

Scenes support add(), create(), enter(), exit(), clear(), save(), load(), and switch(). Scene files use readable JSON. Objects can be marked persistent = True so they survive scene clearing.

Developer mode

modes.developer = True

Developer mode enables the diagnostic overlay and visual collider bounds. Disable it with modes.developer = False.

0.1.1 approach

0.1.1 is an API expansion milestone. The goal is to make common game development tasks — movement, input, timing, object state, hierarchy, collision, spatial queries, scenes, and debugging — available through small Python calls while keeping performance-critical work in the native layer.

Lighting remains intentionally postponed so the renderer can evolve without assuming expensive lighting is suitable for older hardware.
