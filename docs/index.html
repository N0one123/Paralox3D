Installation

Paralox3D is available on PyPI. For a normal installation, use:

python -m pip install paralox3d

Then create a Python file and import the engine:

from paralox3d import *
0.1.0: This documentation describes the public API shipped with Paralox3D 0.1.0. Some parts of the engine are intentionally still early-development features.

Your first game

The smallest useful Paralox3D program can be very small:

from paralox3d import *

cube = Object("cube", position=(0, 0, -5))

def update():
    cube.x += 0.5 * dt

start()

That is the basic idea: create your objects, write what should happen every frame in update(), then call start(). Paralox3D handles the main loop for you.

Basics

Paralox3D deliberately keeps common game code close to plain Python. An Object represents something in your 3D world, and its properties describe where it is and how it looks.

Objects

player = Object(
    "cube",
    position=(0, 1, 0),
    scale=(1, 2, 1),
    name="Player"
)

The first argument is the shape. In 0.1.0, the native renderer provides the basic cube primitive. Position, scale, and name can be supplied when the object is created.

Transforms

You can work with a complete vector or change individual axes. The same style is used for position, rotation, and scale.

cube.position = (2, 1, -5)
cube.x = 3
cube.y += 1

cube.rotation = (0, 45, 0)

cube.scale = (2, 1, 2)
cube.scale.x = 3

This is intentionally flexible: use whichever form makes your game code easier to understand.

Game loop and dt

update() is called once per frame. You do not need to pass a delta-time argument to it. Import dt and use it directly when movement should be frame-rate independent.

from paralox3d import *

player = Object("cube", position=(0, 0, -5))
speed = 4

def update():
    player.x += speed * dt

start()

dt represents the time since the previous frame. Multiplying movement by dt means the movement is based on elapsed time rather than simply on how many frames the computer happens to draw.

Camera

The built-in camera gives you a simple starting point while still exposing its position and rotation for more controlled setups.

modes.camera = True

camera.position = (0, 2, 8)
camera.look_at((0, 0, 0))

Position and rotation

camera.x = 0
camera.y = 2
camera.z = 8

camera.pitch = -10
camera.yaw = 0
camera.roll = 0

You can also assign camera.position and camera.rotation as three-value tuples.

look_at()

Instead of calculating camera angles yourself, point the camera at a target:

camera.look_at((0, 0, 0))

The target can be a three-value position or a Vec3-like object.

Mouse controls

With camera mode enabled, the built-in native camera supports mouse controls. Left-drag rotates the camera. Right-drag pans it. The native camera movement is kept separate from ordinary Python transform updates so the controls remain responsive.

Input

Input helpers are designed to read naturally inside update().

if key("space"):
    print("Space is down")

if held("w"):
    player.z -= 5 * dt

if pressed("escape"):
    print("Escape was pressed")

key() checks the current key state, held() is for a key being held, and pressed() is for a press event. Keyboard names include letters, digits, common control keys, and the arrow keys.

Collision

Collision is intentionally simple at the surface, but it is not locked down. Every Object has a configurable collider you can inspect and change.

Basic collision check

if Collision(player, wall):
    print("Player hit the wall")

Find everything touching an object

hits = Collision(player)

for other in hits:
    print("Touching:", other.name)

Control the collider

player.collider.size = (0.8, 1.8, 0.8)
player.collider.offset = (0, 0.1, 0)

player.collider.enabled = False

The default collider follows the object's scale. You can replace its size, move it with an offset, or disable it when your game needs different behaviour.

How it works in 0.1.0: the built-in collider uses axis-aligned bounding boxes (AABBs). It is a practical starting point for simple games, while the exposed collider properties leave room for more controlled gameplay code.

Components

Components provide a place for behaviour that you want to attach to an object rather than putting everything into one large game script.

from paralox3d import Component, Script

Component is the base component type, and Script is the built-in script component. The component system is part of the 0.1.0 foundation and is intentionally small while the engine develops.

Scenes

Scenes are Paralox3D's way of keeping levels or worlds organised. Instead of rebuilding a collection of objects every time you change level, a scene gives that world a named home.

from paralox3d import Scene, current_scene

level = Scene("Level 1")

Scenes are a first-class part of the engine architecture. The 0.1.0 API is deliberately small here; more scene-management functionality can be added without changing the basic idea.

Developer mode

When you are debugging a game, you can turn on developer mode:

modes.developer = True

Developer mode enables the engine's visual and diagnostic debugging tools. In 0.1.0 this includes the developer information overlay and visual collider bounds.

Turn it off when you want a normal presentation:

modes.developer = False

The important idea is that developer mode is a master switch for the engine's visual debug features, so you do not have to manage every debug display separately.

The Paralox3D approach

Paralox3D is meant to sit in a useful middle ground: you should be able to make a first 3D program without fighting the engine, but the simple API should not stop you from taking control when your project grows.

For example, collision can start as one line — Collision(player, wall) — and then become as specific as you need by changing the collider's size, offset, and enabled state. The same philosophy applies throughout the engine: sensible defaults first, direct control when you need it.
